Undaergo — place data NOTICE
============================

The place file distributed beside the installer, `poi-overture.sqlite`, is built from the
Overture Maps Foundation "places" theme. The operator imports it from the Data panel; it is
not inside the installer.

  1. Source: Overture Maps Foundation, theme `places`, type `place`, release 2026-08-19.0.
  2. Extract: Italy, bounding box 6.6,35.4,18.6,47.1, clipped to the Overture divisions
     polygon for Italy simplified to 0.002 degrees.
  3. Built 2026-09-23; format version 2, schema version 1, 116 categories.
  4. Rows: 817,662.

the routing network are OSM-derived and are credited separately as

What was changed for bundling
-----------------------------

  - restricted to the 116 categories the application serves;
  - restricted to records whose coordinates fall inside Italy's national outline;
  - restricted to records with a non-empty name and a confidence above zero;
  - coordinates rounded to 1e-5 degrees (~1.1 m);
  - the confidence score retained as an integer scaled by 1000;
  - the Overture identifier retained as its 16-byte value;
  - the free-form address and locality joined into a single display string;
  - stored in a read-only SQLite table with an R-tree spatial index.

No attribute values are invented, and no place is added. The build is reproducible from the
released source above with `tools/map-data` in the application's source repository.


The database the application installs
-------------------------------------

Importing the place file writes a database under the operator's own data directory. That
database is not the file above: the importer also reads the installed map archive and adds
the place, street and locality names it draws, so that what the map shows and what a search
finds cannot disagree.

Those added rows are OpenStreetMap-derived and are covered by the ODbL (see
LICENSE-ODbL-1.0.txt). The resulting database is therefore a Derivative Database under the
ODbL as well as a collection of Overture records. It stays on the operator's machine and is
never distributed by the application; an operator who passes it on, or publishes it, must
comply with both licences — including the ODbL share-alike obligation.
